# Codebase source-of-truth and conflict register

This file records the current source-of-truth decisions for avoiding duplicate or contradictory implementation paths. It is an engineering register, not a production certification.

## Confirmed canonical paths

| Concern | Canonical path | Rule |
|---|---|---|
| API production startup | `apps/src/production-server.ts` via `node apps/dist/src/production-server.js` | Production startup validates the production environment before importing the server. |
| API implementation | `apps/src/server.ts` and feature route modules in `apps/src/` | Use the production entrypoint for production; `apps/src/server.ts` remains the underlying server and development target. |
| Stakeholder authentication | `apps/src/auth-routes.ts`, `apps/src/auth.ts`, `apps/src/rbac-policy.ts` | Native PostgreSQL-backed sessions; Firebase configuration is not part of the current runtime contract. |
| Production configuration | `apps/src/production-config.ts` | Fail closed on missing/unsafe production settings. |
| Dependency graph | Root `package.json` + committed `package-lock.json` | Use `npm ci` for repeatable installs in CI and Docker. |
| Database schema | Ordered SQL files in `migrations/` + migration validator | Do not edit applied migrations to change production schema; add a new migration and validate ordering/invariants. |
| Container build/start | Root `Dockerfile` | Build from the root lockfile; migrate, then start the production entrypoint. |
| CI validation | `.github/workflows/ci.yml` | CI is a validation gate, not a deployment or production-certification signal. |
| Render declaration | `render.yaml` | Treat as a Blueprint declaration; confirm linkage before applying resource identity changes. |
| Guardian policy build source | `scripts/build-wa03-guardian-policy.mjs` | The generator writes the build bundle to `guardian-policies/WA03.001/`; regenerate rather than hand-edit generated schemas/policy files. |
| Guardian live acceptance | `.github/workflows/guardian-live-acceptance.yml` | Live evidence is required for real Guardian/Hedera acceptance claims. |
| Regulatory authority | `docs/WA03_001_GUARDIAN_POLICY_SPEC.md` and `docs/WA03_001_GUARDIAN_POLICY_MANIFEST.json`, subject to the controlling BEE methodology | Guardian implementation artifacts do not replace the governing BEE methodology. |

## Conflicts identified and disposition

### Guardian WA03.001 duplicate policy snapshots — unresolved

The repository contains multiple policy representations:
- `guardian-policies/WA03.001/policy.json` and its schema files, generated by `scripts/build-wa03-guardian-policy.mjs`;
- `docs/guardian-policy/wa03.001/policy.json`, a structurally different policy snapshot;
- `guardian-policies/RupayKg-WA03.001-v1.policy`, a packaged artifact created by `scripts/package-wa03.ps1`.

The generator and packaging script establish a build path, but do not by themselves prove that every historical snapshot is unused or that the generated bundle passes live Guardian import. Do not import the documentation snapshot as an alternative production policy. Do not delete policy artifacts until references, hashes, and live Guardian import requirements have been checked. The canonical *source generator* is known; live Guardian publication/acceptance remains a separate gate.

### Render Blueprint versus live service name — unresolved

The Blueprint declares `rupaykg-production`, while the existing live service was identified as `rupaykg`. No rename is performed until the Blueprint's resource linkage and change plan are confirmed. Do not create a second production service to resolve a naming mismatch.

### Cloud Build versus Render — distinct responsibilities

`cloudbuild.yaml` builds and pushes a container image. It does not deploy the image to Render. Keep both only if the image registry workflow is intentionally used; otherwise remove the unused pipeline after confirming triggers and consumers.

### CI verification snapshots — historical evidence

Files named `docs/CI_LATEST_WEB_TYPECHECK_VERIFICATION_*.md` are historical marker documents, not the live CI source of truth. Use GitHub Actions run results for current status. Preserve historical files until their evidentiary value and references are reviewed; do not interpret their titles as current pass claims.

## Release discipline

- Passing CI is necessary but does not prove live integration or regulatory acceptance.
- Do not merge until required checks and review are complete.
- Do not enable production certification until Shakti Standards evidence gates, TRL evidence, live stakeholder workflows, security/recovery tests and external trust acceptance have been independently satisfied.

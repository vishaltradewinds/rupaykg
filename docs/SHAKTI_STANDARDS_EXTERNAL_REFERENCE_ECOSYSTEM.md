# Shakti Standards — External Reference Ecosystem

## Purpose

This document defines how RupayKg may use external digital-infrastructure, standards and innovation ecosystems as reference inputs without confusing them with Indian statutory authority or product certification.

## Reference ecosystems

| Reference | Intended use | Authority boundary |
|---|---|---|
| UN Innovation Network | Innovation, institutional learning and scaling patterns | Reference only |
| FAIR Forward / BMZ | Open, inclusive, sustainable and responsible digital/AI practices | Reference only unless separately authoritative |
| Digital Public Goods Alliance | Reusable open-source software, standards and interoperability patterns | Reference only |
| Global DPI Repository | Proven digital-infrastructure architecture, governance and deployment patterns | Reference only |
| Relevant Indian DPI ecosystems | National interoperability and implementation patterns | Use as applicable; authoritative status depends on the specific government source/interface |

## Mandatory adoption sequence

`Reference → Cross-map → Legal/Regulatory Check → Technical Validation → Adapt → Implement → Test → Field Validate → Assure`

No external pattern is adopted solely because it is popular, open source, listed in a repository or recognised by an ecosystem.

## Evidence required before adoption

For every materially reused external pattern, record:

- source identity;
- source version/date;
- purpose;
- RupayKg layer affected;
- applicability;
- Indian legal/regulatory compatibility;
- security/privacy/data-governance impact;
- technical feasibility;
- required local adaptations;
- implementation location;
- automated tests;
- field/production validation;
- residual risk and owner;
- approval status.

## Authority rule

The following hierarchy governs conflicts:

**Indian law/regulation/authoritative scheme requirement → approved RupayKg regulatory profile → validated technical implementation → external reference guidance.**

External reference material cannot relax a statutory, security, tenant-isolation, evidence, MRV or production gate.

## AI and open-source controls

Open-source AI/software may be adopted only after checking:

- licence compatibility;
- dependency provenance;
- security posture;
- model/data provenance where relevant;
- privacy and data-transfer boundaries;
- reproducibility;
- maintainability;
- support/operational ownership;
- failure behaviour;
- human-review requirements.

## Golden control statement

**Reuse what is proven. Verify what is adopted. Localise what is required. Evidence what is claimed.**

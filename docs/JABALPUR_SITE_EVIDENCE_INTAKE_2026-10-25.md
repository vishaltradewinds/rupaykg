- Public records reviewed describe Kathonda as a mass-burning municipal solid-waste waste-to-energy (WtE) facility. A CPCB reply before the NGT dated 25 September 2024 reported that the sanitary landfill constructed for the purpose was not being used properly at that time.
- A reproduced NGT order dated 13 July 2026 reports JMC's account that the WtE plant was recommissioned in January 2026 and operated through June 2026. That is not an independent inspection by RupayKg and does not prove the current state after June 2026.
- The same order discusses a separate proposed 100 TPD Bio-CNG project; its proposal/DPR status is not evidence that the asset has been commissioned or is operating.
- BEE BM WA03.001 is a landfill-methane-recovery methodology. Do not use it for the WtE plant merely because both activities relate to municipal waste.
- BEE's approved-methodology list separately lists BM WA03.003 for production of compressed bio-gas (CBG). Its applicability must be assessed only against the actual, approved, designed, commissioned activity and the current methodology requirements.

## 5. Hardware approval gate — MeitY-only owner rule

The project owner requires hardware only where applicable MeitY approval/certification has been verified for the exact model and scope. Do not assume a universal MeitY certificate applies to every industrial instrument. For each item:
- determine the current statutory/contractual route using official schedules and authority guidance;
- verify exact model and certificate scope from the official authority or obtain written authority confirmation;
- separately check calibration/metrology, Legal Metrology, electrical safety/EMC, radio/telecom/WPC/ETA and sector-specific requirements as applicable;
- retain official source, retrieval date, validity and evidence hash;
- record independent reviewer and decision.

Permitted statuses: VERIFIED, PENDING, HOLD, EXPIRED, REJECTED, or NOT APPLICABLE WITH WRITTEN JUSTIFICATION. The last status cannot silently override the owner's MeitY-only requirement. If a required approval route cannot be resolved, escalate and keep HOLD.

STQC's IoT System Certification Scheme can cover sensing/embedded components, communication protocols, gateways, cloud and interfaces; the relevant certification route and exact product scope must still be established. A listing for a different product category is not proof of approval for the candidate.

## 6. Minimum instrument-to-MRV acceptance matrix

Run only after activity/methodology and exact instrument approval gates pass. Use a controlled test environment first; retain input fixture, expected result, actual result, logs, build/commit, reviewer and evidence hash for every case.

| ID | Test | Required pass condition |
|---|---|---|
| T01 | Instrument identity | Exact registered model/asset matches physical device and observation source |
| T02 | Approval gate | HOLD/PENDING/EXPIRED/REJECTED instrument cannot create eligible MRV observation |
| T03 | Parameter mapping | Instrument is explicitly approved for the exact parameter code; mismatch is rejected |
| T04 | Units/range | Invalid unit, out-of-range or unsupported precision is rejected or quarantined with reason |
| T05 | Calibration | Missing, expired or failed required calibration blocks eligibility |
| T06 | Raw evidence | Original observation retained immutably with source, units, timestamp and provenance |
| T07 | Correction | Correction is additive, reasoned and linked; original value is never silently overwritten |
| T08 | Duplicate/replay | Duplicate event and replayed payload are detected/idempotent or quarantined, never double-counted |
| T09 | Ordering/time | Out-of-order data, timezone errors and clock drift are flagged and handled by documented policy |
| T10 | Offline/reconnect | Buffered readings recover without silent loss or double counting; gaps remain visible |
| T11 | Fault/missing sensor | Disconnection, stale data, malformed value and sensor fault fail closed |
| T12 | Calculation lineage | Each derived MRV value can be recomputed from raw observations and versioned method/configuration |
| T13 | Organization isolation | One organization cannot read/register/review another organization's instruments or decisions |
| T14 | Downstream submission | Ineligible or unverified observation cannot reach Guardian/registry submission path; eligible test path preserves trace IDs and hashes |

A passing software test does not establish physical calibration, field performance, regulatory approval, methodology eligibility or official carbon-credit issuance. Field acceptance needs a separately authorized site test and signed results.
